# 묻다 ↔ 잇다 콘텐츠·기능 경계 — 결정

> 트리거: 사장님 라이브 확인(2026-07). 묻다 길잡이에서 콘텐츠 클릭 시 잇다 앱(잇다 하단탭)으로 튕기는 seam 발견.
> 사장님 결정: *"묻다 콘텐츠는 묻다에서 열리게. 잇다는 자매 서비스로 — 요양원/호스피스/완화의료 정보 검색, 돌봄 기록으로 정리하자."*
> 이번 세션 상위 과업("잇다 정리 — 묻다로 옮겨간 기능 덜어내기")의 경계 확정.

## 결정 (경계)

| 서비스 | 담는 것 | 원칙 |
| :-- | :-- | :-- |
| **묻다** | 유언·상속·장례·돌봄 **콘텐츠**(길잡이 글·에세이), 유언/편지/보관, 체크인 등 | 묻다 콘텐츠는 **묻다 안에서 열린다.** 잇다로 안 튕긴다. |
| **잇다** (자매 서비스) | **요양원/호스피스/완화의료 정보 검색** + **돌봄 기록(케어링)** | 묻다 → 잇다 이동은 이 목적의 **"자매 서비스" 다리 하나로만** 명시. |

- 묻다에서 잇다로 넘어갈 때는 반드시 **"자매 서비스 잇다로 이동합니다 · 같은 계정"** 라벨을 붙인다(사용자가 다른 앱으로 넘어감을 인지). raw 튕김 금지.
- 잇다는 요양/호스피스/완화의료 + 돌봄 기록으로 스코프를 좁힌다. 그 외 콘텐츠(유언·상속·장례·웰다잉 에세이 등)는 묻다 쪽 자산.

## 현재 상태 진단 (2026-07)

- **레포 `mutda/library.html` = 이미 깔끔한 의도 버전.** 묻다 자체 글 2개(`article-will-legal.html`·`article-belongings.html`) + 명시적 다리 카드 1개(`../info.html`로, "요양·호스피스·완화의료 정보는 잇다에서 · 자매 서비스"). **동적으로 잇다 콘텐츠를 끌어오지 않음.**
- **그러나 라이브 화면**엔 잇다 info 글(사전연명의료의향서·웰다잉·상조 가입)이 묻다 길잡이 카드로 섞여 나오고, 클릭 시 잇다 도메인(`info/*.html`, 잇다 하단탭)으로 튕김.
- → **라이브 ≠ 레포.** 원인 후보: ① 묻다 PWA **서비스워커 캐시(옛 library.html)** ② gh-pages 배포 불일치 ③ 다른 버전이 배포됨. **집중 세션에서 라이브 직접 확인 필요.**

## 실행 항목 (집중 세션 · 지하철 아닐 때)

1. **라이브 배선 확인** — 묻다 길잡이가 실제로 잇다 info를 동적 로드하는지, 아니면 SW 캐시된 옛 화면인지 판별. (묻다 `sw.js` CACHE_VERSION·`js/nav.js`·`library.html` 배포본 대조)
2. **캐시/배포 문제면** — 묻다 sw.js 캐시 버전 올려 옛 library.html 축출. 레포 버전이 이미 맞으므로 재배포로 해소될 수 있음.
3. **의도적으로 잇다 글을 끌어온 배선이면** — 그 로드를 제거하고, 묻다 자체 글(article-*)로만 길잡이 구성. 잇다行은 명시적 다리 카드 하나로 축소.
4. **잇다 스코프 좁히기** — 잇다 진입 시 요양원/호스피스/완화의료 검색 + 돌봄 기록을 전면에. (이번 세션의 ltc-search 버그 수정도 이 스코프의 일부 — 별도 재배포 대기 중.)
5. **묻다 → 잇다 다리 카피** — "자매 서비스 잇다로 이동합니다 · 같은 계정으로 바로 열려요" 라벨 유지·강화.

## 헌장 일관성

- ✅ 두 앱 경계 명확화 = 사용자 혼란 감소(seam 제거). 과시·경쟁 없음.
- ✅ 되돌리기 쉬운 프런트/캐시 작업 위주. 실데이터·DB 변경 없음.
- ⚠️ 실제 배포(묻다 재배포)는 집중 세션에서 라이브 확인 후.
